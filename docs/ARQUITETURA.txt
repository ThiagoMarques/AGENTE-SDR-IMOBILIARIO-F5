Arquitetura — Agente SDR Imobiliário (POC Fase 5)
=================================================

Visão
-----
Prova de conceito de um SDR imobiliário com IA generativa. O agente atende
leads, qualifica intenção (compra / aluguel / investimento), consulta imóveis
em uma API fake pública, agenda reuniões e gera resumo para o corretor
(human-in-the-loop).

Stack
-----
- Front: Vite + React + TypeScript (Chat + Dashboard)
- API: FastAPI (Python) em api/app.py
- Banco: PostgreSQL (Docker Compose) via SQLAlchemy
- Imóveis: Fake Real Estate API (externa)
- CLI: main.py (cenários do enunciado)

Fonte de imóveis
----------------
Padrão (IMOVEIS_SOURCE=br): catálogo sintético Brasil em BRL
  (src/imoveis/catalogo_br.py) — regiões SP/DF alinhadas ao agente.
Opcional (IMOVEIS_SOURCE=fake): Fake Real Estate API (EUA):
  https://fakeapifordevs.vercel.app/docs/realestate
  GET /api/realestate/listings

Guardrails do chat
------------------
- Mensagens fora de escopo (clima, esportes, política etc.) não disparam
  busca de imóveis nem poluem o perfil; o agente redireciona ao funil.
- Cards de imóveis só aparecem com intenção + filtro (quartos ou preço).

Componentes
-----------
1) frontend/
   Chat do lead e dashboard do corretor (proxy /api -> :8000).

2) api/app.py
   REST: /chat, /leads, /dashboard, /health, /webhooks/canal (stub).

3) src/agente
   Orquestra a conversa: extrai sinais, atualiza perfil, busca imóveis,
   responde (LLM se houver OPENAI_API_KEY; senão fluxo determinístico).

4) src/qualificacao
   Score e prioridade (quente / morno / frio).

5) src/imoveis
   Cliente HTTP da Fake Real Estate API + normalização.

6) src/memoria + src/db
   Persistência PostgreSQL (leads, mensagens, agendamentos, imoveis_sugeridos).

7) src/agenda / src/resumo / src/dashboard
   Horários, pacote do corretor e métricas.

8) src/crm
   Webhook por evento (lead_atualizado, lead_qualificado, resumo_gerado)
   + CRM simulado em FastAPI (python main.py --crm-servidor, porta 8001).
   Detalhes em docs/QUALIFICACAO_E_RESUMO.md.

Fluxo
-----
Lead (React) -> POST /chat -> memória/perfil (Postgres) -> qualificação
            -> API de imóveis -> resposta (LLM ou regras)
            -> dashboard / resumo para corretor

Subir a POC
-----------
1) docker compose up -d
2) python -m venv .venv && source .venv/bin/activate
3) pip install -r requirements.txt
4) uvicorn api.app:app --reload --port 8000
5) cd frontend && npm install && npm run dev
   -> http://localhost:5173

Variáveis (.env na raiz do projeto)
----------------------------------
DATABASE_URL=postgresql+psycopg://sdr:sdr@localhost:5432/sdr
OPENAI_API_KEY=           # opcional
LLM_MODEL=gpt-4o-mini
IMOVEIS_API_BASE=https://fakeapifordevs.vercel.app/api/realestate
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173

Segurança e privacidade (Fase 5)
--------------------------------
- Credenciais só em .env (não versionado)
- Catálogo via API fake (dados sintéticos)
- Resumo para humano decidir; o agente não fecha contrato sozinho
